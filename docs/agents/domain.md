# Domain docs

This repository has one domain context.

Before exploring or changing the application, read `CONTEXT.md` and any relevant decision in `docs/adr/`. If an ADR directory does not exist yet, continue.

Use the glossary's terms in issues, designs, code, and tests. If a new domain term is needed, resolve its meaning with the user and record it in `CONTEXT.md`.

Flag a proposed change that contradicts an ADR before replacing that decision. Create ADRs only for consequential decisions with a real trade-off.
